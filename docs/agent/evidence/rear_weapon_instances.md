## Confirmed ordering and parameters

Grenade launch obtains the actual mount world position, activates and clears age. It preserves its loaded heading. Update increments age first, projects the previous position to the original track surface, subtracts `4.7*dt` from Y, and snaps to the projected position only when the pre-fall position was at or below that surface. Fuse comparison is `age >= .75`. Explosion includes the owner, visits every participant in order, and uses strict three-dimensional distance `<6`. Every eligible vehicle receives full configured HITPOINTS directly against internal durability, without armor or distance falloff. Force is the unnormalized displacement from explosion to vehicle multiplied by configured acceleration and ammunition mass. Application is the instance position with Y zero, confirmed against the receiver before `004d3ee3` in the retained `0044e310/0044e340` disassembly. Grenades additionally call yaw impulse `0042c0c0`; all use the original linear and tilt impulse paths.

Land and Reactive Mines project/fall using the same `4.7` constant, test contacts, then increment age. Owner immunity compares the previous age with `<2`; it does not protect other participants. Contact tests point-in-footprint using triangles `[0,1,2]` and `[2,3,0]`, then rejects only when all four wheel air times are nonzero (`00428e7e`). First eligible participant receives full internal HITPOINTS and an upward force `(0,acceleration*mass,0)`, applied at the instance XZ position with Y zero. Receiver and position were checked in disassembly near `00456ee0`. There is no grenade-style yaw call. Only Reactive Mines request the additional effect; the shared constructor argument is not a homing flag. No automatic mine expiry or target seeking appears in these update functions.

Arachnoid launch calls shared mine launch and sets heading to owner chassis heading minus 180; direction is the original +Z rotation. Updates animate leg headings by `40*1.5*dt`, toggling phase below -15 and above 10. Horizontal travel is `1.5*dt` along direction and fall is `4.7*dt`. Wall query uses current/current positions, radius 1, and height checks, with the original 100-record local capacity. The one-unit forward segment is tested against each wall. On a hit, one shared `rand()%360` sets heading, position restores to the preceding callback position, and loop index resets to zero before normal increment to one. No speculative reflection or homing is implemented. Surface clamping follows wall handling, then the shared mine contact and age increment.

## Portable integration contract and validation

`RearInstanceWorld` requires original ground projection and Arachnoid wall-query services; Arachnoid wall hits additionally require the shared random stream. Missing services return `unavailable`. The kernel emits ordered internal-damage and force commands; the coordinator must apply linear, tilt and optional yaw impulses with scalar **1.0, not simulation dt**, braking false and tilt fixed-radius false. Grenade yaw uses fixed lever -1. These call arguments are present in the retained explosion/contact decompilation. The coordinator must own visual/audio/callback lifecycle effects. It must supply actual mesh mount positions, owner headings, footprints, wheel air times and asset parameters. There are no generic rigid-body replacements.

`tests/core/rear_weapon_instances_test.cpp` checks duplicate launch, preserved grenade heading, surface penetration/snap ordering, exact fuse and radius boundaries, owner blast damage, unnormalized impulse, owner mine arming order, airborne restrictions, no invented expiry, Reactive-only extra effect, Arachnoid travel/leg motion and one-draw wall reorientation, missing RNG, and stop cleanup. Standalone C++20 build with `-Wall -Wextra -Wpedantic` and test execution passed. This establishes kernel behavior coverage; native rendering, audio and full race integration are not established by that test. No full-function verified status is claimed.
